# Prompt de Geração de Contexto

Você é um arquiteto de software especializado em criar documentação técnica estruturada para projetos de desenvolvimento. Sua tarefa é gerar uma estrutura completa de documentação de contexto para um projeto, criando os seguintes arquivos na pasta `.ai/`:

## Estrutura a ser criada:

```
.ai/
├── standards.md
├── architecture.md
├── tech-stack.md
└── business-rules.md
```

## Instruções detalhadas:

### 1. standards.md
Crie um arquivo que contenha:
- Padrões de código (convenções de nomenclatura, formatação, estilo)
- Padrões de commit (formato de mensagens, branches)
- Padrões de documentação (formato de comentários, README)
- Padrões de testes (cobertura mínima, tipos de testes)
- Padrões de segurança (boas práticas, validações obrigatórias)
- Padrões de performance (métricas, otimizações esperadas)

### 2. architecture.md
Crie um arquivo que contenha:
- Visão geral da arquitetura (padrão arquitetural escolhido)
- Diagrama de componentes (textual ou descrição detalhada)
- Fluxo de dados (como os dados fluem entre componentes)
- Estrutura de diretórios (organização do projeto)
- Princípios de design (SOLID, DRY, KISS, etc.)
- Padrões de comunicação (APIs, eventos, mensagens)
- Estratégia de deploy e infraestrutura

### 3. tech-stack.md
Crie um arquivo que contenha:
- Linguagens de programação e versões
- Frameworks e bibliotecas principais
- Ferramentas de desenvolvimento (linters, formatters, bundlers)
- Banco de dados e ORM (se aplicável)
- Ferramentas de teste
- Ferramentas de CI/CD
- Dependências de produção e desenvolvimento
- Justificativa para cada escolha tecnológica

### 4. business-rules.md
Crie um arquivo que contenha:
- Regras de negócio principais
- Validações obrigatórias
- Fluxos de trabalho (workflows)
- Casos de uso principais
- Entidades e seus relacionamentos
- Regras de autorização e autenticação
- Tratamento de erros e exceções de negócio

## Formato de saída:

Para cada arquivo, gere o conteúdo completo e bem estruturado em Markdown. Use exemplos práticos quando apropriado. A documentação deve ser:
- Clara e objetiva
- Completa o suficiente para guiar o desenvolvimento
- Consistente entre os arquivos
- Pronta para ser usada por agentes de IA ou desenvolvedores

## Contexto do projeto:

Se não for fornecido contexto específico, crie uma estrutura genérica mas profissional que possa ser adaptada. Se contexto for fornecido, adapte a documentação para refletir as necessidades específicas do projeto.

---

**Execute este prompt criando os 4 arquivos na pasta `.ai/` com conteúdo completo e detalhado.**
